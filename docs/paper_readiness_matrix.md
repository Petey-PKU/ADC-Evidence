# ADC-Evidence 投稿准备矩阵

这份矩阵把当前代码状态与论文可声称的证据分开。它用于下一轮实验排程，
不代表已经满足任何特定期刊或会议的投稿要求。

| 审稿关注点 | 当前证据 | 状态 | 下一步验收 |
|---|---|---|---|
| 可复现实验实现 | 公共代码、固定版本、148 项测试、`ADC_OFFLINE_ONLY` 网络模型禁用开关 | 已具备 | CI 在干净环境重跑并保存日志 |
| 数据与题集隔离 | 原 120 题标为 `development_exposed`；另有 20 题公开 holdout | 部分具备 | 建立更大、领域策划、未参与开发的保留集 |
| 结构化路由贡献 | 字段级查询、缺字段拒答、精确 PMID/NCT 路由 | 工程证据 | 在保留集上报告逐题语义正确率 |
| 引用与证据支持 | 引用完整性和文本支持校验；精确主题门槛 | 工程证据 | 增加人工标注的引用相关性与完整性分数 |
| 基线公平性 | 同一数据库的离线抽取式 RAG 基线 | 已具备初版 | 在揭盲前锁定检索预算、生成器和统计口径 |

## 当前可以写入论文的方法贡献

1. 将结构化事实查询、原子结论、来源引用和证据不足处理放入同一条可审计流程。
2. 对明确的 PMID/NCT 使用标识符直达检索，降低长中文问题导致的漏召回。
3. 对精确结论设置主题证据门槛，避免“相关文献”被误当作“直接证据”。
4. 将已暴露题集、公开 holdout 和私有评审记录分开管理，并在报告中记录用途。

## 当前不能写入论文的结论

- 不能称作独立专家复核或临床事实金标准。
- 不能把公开 20 题 holdout 的自动指标写成临床准确率。
- 不能把系统与离线基线的差异全部归因于某一个组件。
- 不能声称达到顶会接收标准；接收取决于完整保留集、评审质量、贡献新颖性和目标 venue。

## 每轮迭代的验收规则

每个改动必须同时留下：代码提交、测试结果、题集/数据库哈希、失败样例和对论文主张范围的更新。
若改动使用私有数据发现问题，必须在公共仓库用公开样例和测试复现，禁止复制私有内容。

`scripts/audit_paper_readiness.py` 提供失败即显式报告的投稿前审计；默认会阻塞在真实人工标签
和独立封存保留集，直到用户提供这两类外部证据。

公共代码还提供 `run_identifier_routing_ablation.py`，固定数据库、题集、生成器和网络状态，
只移除显式 PMID/NCT 精确路由。公开 20 题不包含 PubMed/NCT 记录，因此不能用它声称该
组件有效；该消融应在包含这些记录的私有或经许可领域评测集上运行，并将结果留在对应边界。

公共代码还提供 `paired_binary_summary`，用于在真实复核标签上计算 bootstrap 差值区间和
McNemar 精确双侧 p 值。它记录标签语义由调用方定义，并拒绝不等长输入；自动路由或状态
匹配率不得直接作为该函数的“正确率”输入。
