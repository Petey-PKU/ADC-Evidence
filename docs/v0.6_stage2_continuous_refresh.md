# v0.6 阶段 2：持续采集与安全增量发布

状态：已实现
完成日期：2026-08-21
策略版本：0.6.0
数据库模式版本：0.6-refresh-v1

## 1. 阶段目标

阶段 2 把阶段 1 的事实历史层扩展为一条可以被计划任务调用的安全刷新链路：外部数据先写入
暂存数据库，逐来源记录运行结果，通过质量门禁后才更新检索语料和向量索引；发布前备份
线上数据库，数据库或索引任一步切换失败都会恢复旧资产。

本阶段不直接配置京东云计划任务，不改写现有生产数据库，也不采集真实远程数据。生产
计划任务与监控接入属于阶段 6；本阶段提供可调度命令、公开离线测试和发布协议。

## 2. 刷新流程

```text
取得互斥锁
  -> 事务一致地复制线上 SQLite 到暂存目录
  -> 分来源采集（有限重试）
  -> 保存来源运行状态和完整记录清单
  -> 完整性 / 数量骤降 / 记录缺失 / SQLite 门禁
  -> 仅改写受影响的检索文档、分块和 FTS 行
  -> 重建当前规模的稠密向量矩阵并绑定语料版本
  -> 生成数据库、索引和策略版本发布清单
  -> 备份线上数据库
  -> 文件级原子替换数据库和索引；任一步失败则自动回滚
```

门禁不通过时，命令保留暂存目录、质量报告和 rejected manifest，线上数据库与索引不会
发生变化。

## 3. 逐来源运行状态

新增表：

| 表 | 用途 |
|---|---|
| ingestion_source_runs | 保存每个采集运行、每个来源的状态、尝试次数、预期/实际数量和完整性 |
| source_run_records | 保存完整采集集合中的来源记录 ID，用于跨运行比较 |

来源运行状态为 running、complete、partial、failed 或 skipped。status 表示本次请求是否按
既定范围成功完成，is_complete 表示结果是否覆盖该来源的完整查询集合；二者不能混用。

例如 PubMed 默认按相关度取前 200 条。如果 200 条全部取得，状态为 complete；当总匹配数
大于 200 时 is_complete 为 false，并记录 planned_truncation。该结果可以用于检索更新，但
不能用于判断某篇文献从来源中消失。

采集异常使用有限指数退避重试。默认最多尝试 3 次，等待 1 秒、2 秒；ADCdb 单条失败、
ClinicalTrials.gov 非预期截断或预期返回条数未全部取得会保存为 partial/failed，并触发
source.collection_failed。

## 4. 发布质量门禁

默认阻断条件：

- SQLite integrity_check 失败或存在外键错误；
- 任一计划采集来源没有 complete 状态；
- 某来源实际记录数较最近一次成功运行下降 25% 以上；
- 完整来源快照相对上一次完整快照出现记录缺失；
- 缺失记录数超过 0。

只有当前和上一批都是完整来源快照时才生成 source.record_missing。partial、failed、skipped
及有意截断的结果永远不能把“本次没取到”解释成“来源已删除”。阈值可以通过命令参数调整，
但生产环境调整前应先检查 rejected manifest 中的具体记录。

## 5. 增量语料与索引绑定

检索文档哈希覆盖标题、正文、来源 URL 和元数据；分块哈希覆盖标题、正文和过滤元数据。
每次刷新先比较新旧文档哈希，只删除并重写新增、变化或消失文档对应的 text_chunks 与 FTS
行，未变化文档不写入。

当前稠密索引仍使用 NumPy 精确余弦矩阵。由于矩阵是一个整体文件，本阶段在语料变化后
重建完整向量矩阵；这不影响数据库中的文档/分块增量更新。索引 manifest 新增
retrieval_corpus_version。加载稠密索引时会重新计算活动数据库的语料版本，不匹配则拒绝
加载，避免数据库和索引错配后静默返回错误证据。

## 6. 发布清单与回滚

每个 ready/published manifest 包含：

- release ID、采集 run ID 和创建/发布时间；
- 数据库 SHA-256、文件大小和全部模式版本；
- evidence policy 版本；
- retrieval_corpus_version 和增量更新摘要；
- 向量索引 manifest 及三个索引文件的 SHA-256；
- 完整质量门禁报告；
- 发布前数据库备份和旧索引回滚位置。

发布使用同目录 incoming 资产和 os.replace 进行文件级原子替换。数据库与索引是两个文件
系统对象，切换之间存在极短窗口；检索器的语料版本校验保证窗口内不会静默使用错配稠密
索引。任一替换、校验或 manifest 写入失败都会恢复备份数据库和旧索引。阶段 6 可进一步
通过版本目录加单一活动指针实现整个资产组的一次性切换。

## 7. 命令与计划任务接口

完整刷新：

```powershell
python -m adc_evidence.refresh `
  --database data/processed/adc_evidence.db `
  --index artifacts/vector_index `
  --staging-root data/refresh_staging `
  --backup-dir data/backups `
  --release-dir data/releases
```

离线验证发布链路，不访问外部来源：

```powershell
python -m adc_evidence.refresh `
  --backend hashing `
  --skip-adcdb --skip-trials --skip-pubmed
```

生产语义检索应使用默认 sentence-transformers 后端，hashing 只用于离线流程测试。成功发布
返回退出码 0；质量门禁拒绝发布返回 2；未处理异常返回 1。调度器应分别告警，不能把退出码
2 当成成功。

同一数据库默认使用同目录 refresh.lock 防止并发刷新。若进程异常退出遗留锁文件，必须先
确认没有刷新进程仍在运行，再由运维人员处理；程序不会自动抢占未知锁。

## 8. 已验证路径

公开自动测试覆盖：

- 暂时失败后按 0.5、1.0 秒指数退避并在第三次成功；
- 第二个刷新进程无法取得同一锁，正常退出后锁释放；
- 部分失败不产生记录缺失，两个完整快照才允许判断缺失；
- 完整空响应同时触发数量骤降和记录缺失门禁；
- PubMed 有意截断明确关闭缺失检测但不伪装成采集故障；
- 重复构建不改写语料，单条 ADC 变化只重写对应文档和分块；
- 数据库语料变化后旧稠密索引拒绝加载；
- 完全离线的暂存发布生成数据库、索引和 published manifest；
- 门禁拒绝时线上数据库、索引和备份目录均不变化；
- 模拟索引切换失败后，旧数据库和旧索引自动恢复。
