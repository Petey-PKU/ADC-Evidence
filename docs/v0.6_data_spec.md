# v0.6 数据与证据规范

状态：阶段 0 基线
机器可读策略：configs/evidence_policy.json

## 1. 设计原则

v0.6 将“当前 ADC 档案单值”升级为“带时间和证据的原子事实”。系统必须分别保存：

- 来源原始快照；
- 标准化来源记录；
- 从来源提取的原子事实；
- 事实对应的原文或结构化字段位置；
- 同一事实的历史版本和来源冲突；
- 人工审核及其内容哈希。

任何层都不得以删除旧值的方式表达更新。

## 2. 标识和时间语义

### 2.1 稳定标识

| 对象 | 标识规则 | 示例 |
|---|---|---|
| ADC | 项目稳定 ID，不随名称变化 | adc_001 |
| 临床试验 | 注册机构 ID | NCT06394492 |
| PubMed 文献 | PMID | 39164784 |
| 来源快照 | 来源、记录 ID、内容哈希确定 | clinicaltrials:NCT06394492:hash |
| 原子事实 | 主体、谓词、标准化值和有效版本确定 | 实现阶段生成稳定哈希 ID |
| 变化事件 | 前后事实版本和检测运行确定 | 实现阶段生成稳定哈希 ID |

实体名称、别名和公司名称不能充当数据库主键。无法高置信度关联的记录进入隔离队列，
不得自动新建一个看似相同的 ADC。

### 2.2 时间字段

| 字段 | 含义 |
|---|---|
| fetched_at | 本系统取得来源内容的时间 |
| source_updated_at | 来源声明的最后更新时间；来源不提供时为空 |
| valid_from | 当前事实版本开始生效的已知时间 |
| valid_to | 被新版本替代的时间；当前事实为空 |
| detected_at | 本系统发现变化的时间 |
| reviewed_at | 人工完成审核的时间 |

界面不得把 fetched_at 写成“来源更新时间”。

## 3. 数据层级

    ingestion_run
      -> source_snapshot（不可变）
      -> normalized_record
      -> fact_observation（某来源观察到的值）
      -> canonical_fact（当前/历史/冲突状态）
      -> change_event
      -> retrieval_document / text_chunk
      -> answer_claim / review

现有 source_records、documents、trials、evidence、retrieval_documents 和 text_chunks 可以
兼容保留。阶段 1 通过迁移新增快照、事实、事实证据和变化事件表，不在阶段 0 直接改变
生产数据库。

## 5. 来源权威与冲突策略

来源优先级按字段定义，不存在一个适用于所有字段的“全局最权威来源”。

| 字段组 | 首选来源 | 后备来源 | 冲突处理 |
|---|---|---|---|
| 临床试验状态、阶段、终点、日期 | ClinicalTrials.gov | 无 | 注册字段为当前值；历史快照保留 |
| PubMed 标题、摘要、日期、类型 | PubMed | 无 | PubMed 元数据为当前值；摘要不得外推全文结论 |
| ADC 结构字段 | ADCdb | 公开种子数据 | 不自动裁决跨来源冲突，进入审核 |
| ADC 研发状态和企业 | ADCdb、ClinicalTrials.gov 关联记录 | 公开种子数据 | 语义不完全等价，必须保留来源并审核 |
| 文献机制和研究结论 | PubMed 摘要中的直接文本 | 其他公开摘要 | 只能生成有直接支持的原子结论 |

curated_seed 是公开演示和回归数据，不是外部权威来源。它可以在真实来源缺失时展示，
但必须标记来源类型，不能伪装成已实时核查的数据。

冲突规则：

1. 同一来源的新快照替代旧快照时，创建历史版本和变化事件。
2. 不同来源出现不同值时，创建并存观察值和 conflicted 当前状态。
3. 只有策略明确指定 authoritative_first 的字段才能自动选择首选来源。
4. 审核者可以确认展示值，但不得删除反对证据。
5. 生成模型不得参与权威来源裁决。

## 6. 状态规范

### 6.1 事实状态

| 状态 | 含义 |
|---|---|
| current | 当前策略下采用的事实版本 |
| superseded | 已被同来源或已审核新版本替代 |
| conflicted | 存在未解决的跨来源不一致 |

### 6.2 审核状态

| 状态 | 含义 |
|---|---|
| needs_review | 尚未完成人工审核 |
| reviewed_supported | 证据支持事实或结论 |
| reviewed_unsupported | 证据不支持事实或结论 |
| reviewed_conflicted | 审核确认仍存在来源冲突 |
| superseded | 审核对象内容已被新版本替代 |

审核必须绑定内容哈希。哈希变化后，旧审核记录保留，但当前对象重新变为 needs_review。

## 7. 变化事件规范

| 事件类型 | 默认严重度 | 是否要求审核 | 示例 |
|---|---|---|---|
| source.collection_failed | high | 否 | 数据源连续抓取失败 |
| source.record_missing | high | 是 | 上次存在的试验本次来源中消失 |
| adc.record_created | medium | 是 | 新识别 ADC |
| adc.development_status.changed | high | 是 | investigational 变为 approved |
| adc.structure.changed | high | 是 | payload 或 DAR 发生变化 |
| trial.record_created | medium | 否 | 新增 NCT 记录 |
| trial.overall_status.changed | high | 是 | RECRUITING 变为 SUSPENDED |
| trial.phases.changed | high | 是 | 阶段字段变化 |
| trial.primary_outcomes.changed | high | 是 | 主要终点变化 |
| publication.record_created | medium | 否 | 新增 PubMed 文献 |
| fact.conflict_detected | high | 是 | 两个来源给出不同 DAR |
| fact.conflict_resolved | medium | 是 | 原有来源冲突因新证据变为一致 |
| fact.value_changed | medium | 是 | 没有专用事件类型的规范字段发生变化 |

来源暂时不可用不能立即生成 source.record_missing。只有采集运行整体成功且来源明确返回记录
集合后，才能判断记录消失；否则只记录采集失败。

## 8. 新鲜度规范

建议生产门槛：

| 来源 | 计划采集 | 最大允许陈旧时间 | 超时行为 |
|---|---|---:|---|
| ClinicalTrials.gov | 每日 | 48 小时 | 页面警告，变化报告标记不完整 |
| PubMed | 每周 | 240 小时 | 页面警告，不声称“最近一周完整” |
| ADCdb | 每周 | 336 小时 | 字段标记可能过期 |
| 公开种子数据 | 手动 | 不适用 | 始终标记为演示/回归来源 |

最大允许陈旧时间是产品服务级别目标，不代表来源本身更新频率。

## 9. 数据质量发布门禁

一次新数据版本只有同时满足下列条件才能发布：

- 采集运行状态成功，来源版本和参数已记录；
- 原始快照存在且 SHA-256 可重新计算；
- 主键、外键和唯一性检查通过；
- ADC、试验和文献数量变化未超过配置阈值，或异常已人工确认；
- 关键字段枚举、日期和 JSON 结构校验通过；
- 无高置信实体关联循环或一对多歧义未隔离；
- 变化事件可以回溯前后快照；
- 检索索引绑定即将发布的数据库版本；
- 自动测试和固定回归集通过；
- 发布前备份已完成且回滚步骤可执行。

## 10. 仓库与隐私边界

公开仓库允许保存通用模式、策略、代码、测试、公开样例和匿名汇总指标。以下内容不得进入
公开仓库：

- 真实 API key、服务器凭据和 .env；
- 评审者身份、原始私有审核导出和个人材料；
- 未经许可再分发的全文或批量原始语料；
- 生产数据库、模型缓存和生成索引；
- 绝对本机路径和内部部署秘密。
