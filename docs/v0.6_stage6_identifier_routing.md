# v0.6 Stage 6: explicit source-identifier routing

## Problem

Ranked sparse or hybrid retrieval can miss a publication when a user supplies
a PMID inside a longer natural-language question. That failure is especially
misleading because the requested record may already exist in the local corpus.

## Change

`HybridRetriever.identifier_search()` now resolves explicit `PMID` and `NCT`
identifiers against the selected local database before ranked retrieval. The
normal ranked path remains the fallback when no exact record is found. The
answering service uses this path only for literature and clinical-trial
questions, and the evidence guard still verifies that the returned record
contains the requested identifier.

The evidence guard also requires a direct lexical anchor for high-precision
intents such as bystander effect, resistance reversal, release rate, MTD, ORR,
and half-life. A generally related abstract is refused when it does not
contain the requested topic.

## Evaluation boundary

This is a retrieval-recall fix. It does not establish that every returned
abstract supports the user’s requested conclusion. Citation relevance and
semantic completeness still require the evidence-support validator and the
documented AI-assisted/human review process.
