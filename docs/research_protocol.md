# ADC-Evidence 研究执行协议

协议版本：`research-protocol-v2-2026-09-12`。初版分析计划在探索性运行前制定；本修订版
在完整题集已用于开发后更新，不能追溯声称对旧题集预注册。代码与题集冻结不等于数据、
人工金标准或论文验证通过。当前不使用远程模型，下一轮确认性评测需要新的独立保留集。

题面文件未损坏；此前乱码来自终端显示。既有测试使用及自定义数据库绑定问题见
[题集审计与更正](question_audit_2026-09-12.md)。现有三组流程保留作历史工程协议，
不代表已获授权继续调用外部模型，也不代表正式三组实验已经完成。

## 研究问题与范围

研究问题：在 HER2/TROP2 ADC 信息核查任务中，结构化事实路由、字段级证据和结论验证，
能否提高回答的正确性、完整性和可追溯性，并降低证据冲突和缺失时的误导性回答？

候选贡献是时间化事实与来源记录、原子结论证据绑定，以及配套评测方法。是否有效由
实验决定，不以功能数量、代码规模或部署成功作为研究结论。研究范围为研发信息检索，
不评价个体治疗决策或临床疗效。

预设假设：

- H1：结构化事实路由提高多字段问题的完整正确率。
- H2：字段证据绑定与结论验证降低无依据结论及错误来源的比例。
- H3：历史版本与冲突保留机制改善变化、冲突和来源缺失任务的处理结果。

H1/H2/H3 都是待检验假设。目前不得使用“已证明提高”“优于通用模型”等表述。

## 执行次序

| 步骤 | 交付物 | 完成条件 |
|---|---|---|
| 1. 冻结实现与题集 | Git 提交、研究标签、题集哈希、测试记录 | 明确锁定代码和题集；不宣称冻结了尚不存在的实验数据 |
| 2. 正式三组运行 | 360 个回答、来源记录、运行清单、盲评包 | 数据前提齐全，三组同窗，运行无缺题；错误和失败运行完整保留 |
| 3. 人工复核 | 第一/第二复核、裁决、原始一致性、分组统计 | 有真实独立评审者；缺失或分歧未裁决时不发布结论 |
| 4. 消融评测 | 普通 RAG 与移除组件的对照结果 | 固定配置、数据、模型、问题和分析口径；不根据测试结果调参 |
| 5. 鲁棒性评测 | 时间切分、缺失、冲突等实验 | 历史或合成来源标明；合成变化不能称为真实世界验证 |
| 6. 投稿材料 | 稿件、图表、复现说明、局限 | 按实际结果选择论文类型与目标刊会 |

后续步骤的分析方案可以预先准备。依赖真实数据、模型输出或人工评分的结果不能提前填入。

## 第 2 步开始前的必要条件

1. 指定独立评测数据集。先检查实体、文献、试验、快照、事实、变化事件数量，不能把
   历史质量报告当作当前数据库状态。公共演示种子不自动视为人工金标准。
2. 记录数据库、索引、来源快照及采集/解析版本的哈希。固定检索后端、top-k 和生成器；
   同一评测窗口内不刷新或修改数据。运行前后验证数据语义版本不变。
3. 明确数据截止时间和统一的“截至何时”语义。数据库观测时间不等于来源事实发生时间。
   变化任务需要足够的历史观测；没有历史时只能报告数据缺口。
4. 当前固定离线生成器与本地检索，不加载远程模型配置。若另行选择外部三组方案，才检查
   对应凭据；日志只记录配置状态，禁止打印密钥。
5. 在开发集完成连接检查后确定正式窗口。所有正式题目只运行预先指定的配置；失败重试
   单独记录原因和用量。不得反复采样后选择最好的回答。
6. 确定真实评审人员、标注规则和裁决安排。模型自动评分不能冒充第二位专家。

## 三组实际配置及解释范围

以下为原三组设计。当前执行方向为完整离线系统与相同证据上的确定性抽取式检索对照；
该对照的独立运行与正式保留集尚未完成，不能沿用外部三组名称发布结果。模型生成文本
与专家评分都不能伪造，也不能用自动路由分数替代答案质量。

| 组别 | 当前实现 | 可以回答的问题 |
|---|---|---|
| direct_model | 指定通用模型，不提供联网搜索 | 模型已有知识的回答表现 |
| web_model | 同一外部模型，每题一次 Tavily basic search，最多五个片段 | 该固定搜索配置下的表现 |
| adc_evidence | 结构化查询；文献路径使用 ExtractiveGenerator | 当前确定性系统在固定本地证据下的表现 |

`run-system` 当前没有使用与外部组相同的 LLM。三组结果可作为端到端系统比较，不能把差值
全部归因于检索、验证器或模型本身；联网组也不能被描述为所有联网助手的最强能力。
第 4 步需要同一模型、同一语料和相同预算的标准 RAG 对照来隔离组件贡献。

范围限制与医疗安全分别评估。例如通用模型正确回答开放域事实，不应仅因它没有遵守 ADC
产品边界就计为医学幻觉或安全错误。证据不足题的 gold 必须明确是“冻结本地语料不足”还是
“公开世界没有已知答案”，不把两者混为一类。

## 人工评审与主要指标

原三组工程协议第一复核覆盖 120 题三组回答、45 题追加第二复核，共 495 次答案级判断。
这不是投稿通用门槛；新的离线方案按实际组数、题数与双评范围重新计算评审量。
原子结论审核与裁决会额外增加工作量。评审资格、培训和利益冲突公开说明，身份映射和
自由文本备注留在私有评测环境。两位独立复核者先各自提交，再查看分歧；同一人的两个账号
或模型扮演专家不构成独立复核。裁决安排和未解决分歧应明确记录。

主指标为可回答测试题的完整正确率：答案正确、覆盖问题必需信息、证据支持且没有误导性
附加结论才算通过。它需要从真实复核字段按预设组合计算，当前 benchmark 汇总功能
不应自动被解释为已经实现了本协议全部统计。

同时分别报告：

- 全部可回答题中实际回答比例，以及已回答题的正确率，防止靠大量拒答提高表面正确率；
- 原子结论支持率、引用来源对应、完整性和错误来源分类；
- 证据不足拒答、医疗安全拒答、产品范围拒答各自的精确率和召回率；
- 每组程序错误、模型拒绝、搜索失败、延迟、token 用量及成本；
- 七个类别的结果和样本量，尤其披露每个类别测试题较少的局限。

现有 0/0.5/1 的人工评分作为描述性次指标，与严格通过率分开。若某项对直接回答组
不适用（例如没有外部引用），记录不适用，不自动记成引用正确或错误。

## 统计分析计划

- 在裁决前的双人样本上，分别对答案、证据、引用和拒答报告一致率、列联表及 Cohen's
  kappa；如采用有序权重，事先声明权重。常数标签导致 kappa 不可定义时说明原因。
- 完整正确率及比例报告分母和 95% 置信区间；小类别不只展示百分数。
- 旧三组方案预设两项主对比：系统对直接模型、系统对联网模型。新离线方案应在保留集
  揭盲前单独锁定对比与统计计划；不得直接套用旧三组主检验。二元成败使用配对 McNemar 检验，
  不一致对很少时用精确形式，并对这两项主检验做 Holm 校正。
- 差值置信区间以题目为配对重采样单位；结论数和多次采样不是新的独立问题。
  同一 ADC 的相关题目可能相关，增加按实体聚类的敏感性分析并说明实体数较少。
- 成本和延迟同时展示中位数、分位数及失败调用；没有计费凭据时只报告用量，估算与
  服务端实际值分列。不能把搜索 credits 估算当作服务端返回值。
- 不以显著性替代效应量和实际用途。样本量目标以预期效应、题目相关性和评审能力设计，
  不把任意题数或准确率门槛描述为所有期刊共同要求。

## 第 4、5 步预设实验

消融候选：普通 BM25-RAG、dense/hybrid 检索、无结构化路由、无结论验证、无字段证据绑定、
无冲突处理，以及完整系统。先在开发数据定义可以比较的配置，保留相同的模型、语料、
检索预算和回答预算。部分能力关闭会改变可回答任务，应报告覆盖率及未回答项。

鲁棒性候选：实体别名和问法变化、删除来源、跨来源冲突、空响应与记录消失、历史日期查询、
时间切分及新来源保留集。合成实验用公开夹具实现；真实时间评估必须有独立时点的来源快照。

正式测试结果暴露的问题可以进入回归集，但不据此重新宣称对原测试集的独立验证。
后续改进的确认性结论需要额外保留集或明确标注为事后分析。
