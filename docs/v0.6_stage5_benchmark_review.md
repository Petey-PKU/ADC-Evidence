## 3. 三组对照

三组必须使用相同的 `evaluation_window_id`、题集哈希和 prompt 版本：

1. `direct_model`：通用模型直接回答，明确关闭联网；
2. `web_model`：同类通用模型启用联网，要求提供直接来源与访问时间；
3. `adc_evidence`：本系统固定实现和运行时数据版本。

每份运行报告记录系统/模型、运行时间、联网标记、prompt 版本、题集哈希和每题状态。
本系统额外记录数据版本、路由、原子结论、引用、校验状态、延迟和输出哈希。自动诊断只
用于发现状态、路由、引用和程序错误，不能作为语义正确率。

### 3.1 运行命令

先创建一个不可复用的同窗标识，例如 `2026-08-21-window-01`：

```powershell
python -m adc_evidence.evaluation.benchmark manifest
python -m adc_evidence.evaluation.benchmark prepare-request --arm direct_model --window-id 2026-08-21-window-01 --output artifacts/evaluation/v0.6_benchmark/direct_request.json
python -m adc_evidence.evaluation.benchmark prepare-request --arm web_model --window-id 2026-08-21-window-01 --output artifacts/evaluation/v0.6_benchmark/web_request.json
python -m adc_evidence.evaluation.benchmark run-system --window-id 2026-08-21-window-01 --output artifacts/evaluation/v0.6_benchmark/adc_report.json
```

外部运行返回的 JSONL 每行至少包含 `question_id`、`status` 和 `answer`。将真实模型名称和
运行时间显式写入报告：

```powershell
python -m adc_evidence.evaluation.benchmark import-external --arm direct_model --responses direct_responses.jsonl --model MODEL_ID --evaluated-at TIME_ISO8601 --window-id 2026-08-21-window-01 --output artifacts/evaluation/v0.6_benchmark/direct_report.json
python -m adc_evidence.evaluation.benchmark import-external --arm web_model --responses web_responses.jsonl --model MODEL_ID --evaluated-at TIME_ISO8601 --window-id 2026-08-21-window-01 --output artifacts/evaluation/v0.6_benchmark/web_report.json
python -m adc_evidence.evaluation.benchmark assemble --direct-report artifacts/evaluation/v0.6_benchmark/direct_report.json --web-report artifacts/evaluation/v0.6_benchmark/web_report.json --system-report artifacts/evaluation/v0.6_benchmark/adc_report.json
python -m adc_evidence.review.prepare_review
```

`assemble` 拒绝题集、同窗或联网标记不一致的报告，并分别生成盲评包和身份映射。运行产物
位于已忽略的 `artifacts/evaluation/`，不得提交原始回答、身份映射或人工复核导出。

### 3.2 硅基流动 + Tavily 开发集 pilot

`dev-pilot` 只稳定抽取 8 道开发集题，每个已有开发类别 2 道，不读取 80 道冻结测试题。
直接回答组和联网组都固定使用 `deepseek-ai/DeepSeek-V4-Flash`；联网组每题执行一次
Tavily basic search。把 Key 放在仓库外的私有 `.env` 时，通过显式路径注入，程序不会向
上级或相邻目录自动搜索配置文件：

```powershell
$env:ADC_ENV_FILE='PATH_TO_PRIVATE_ENV'
python -m adc_evidence.evaluation.benchmark run-external --arm direct_model --scope dev-pilot --window-id WINDOW_ID --output artifacts/evaluation/v0.6_benchmark/pilot_direct_report.json
python -m adc_evidence.evaluation.benchmark run-external --arm web_model --scope dev-pilot --window-id WINDOW_ID --output artifacts/evaluation/v0.6_benchmark/pilot_web_report.json
python -m adc_evidence.evaluation.benchmark run-system --scope dev-pilot --window-id WINDOW_ID --output artifacts/evaluation/v0.6_benchmark/pilot_adc_report.json
python -m adc_evidence.evaluation.benchmark assemble --scope dev-pilot --direct-report artifacts/evaluation/v0.6_benchmark/pilot_direct_report.json --web-report artifacts/evaluation/v0.6_benchmark/pilot_web_report.json --system-report artifacts/evaluation/v0.6_benchmark/pilot_adc_report.json --packet artifacts/evaluation/v0.6_benchmark/pilot_blind_review_packet.json --identity-map artifacts/evaluation/v0.6_benchmark/pilot_blind_identity_map.json
python -m adc_evidence.review.prepare_review --benchmark-packet artifacts/evaluation/v0.6_benchmark/pilot_blind_review_packet.json
```

2026-08-24 的链路验证共运行 8 题：直接组成功 8/8（6 回答、2 拒答，6,568 tokens），
联网组成功 8/8（8 回答，23,141 tokens，8 次 basic search，7 个回答实际引用网页来源），
本系统为 3 回答、5 拒答且无程序错误。它确认了三组运行、来源记录、盲化和导入链路，
也暴露出公开样例的临床试验数据缺口；这些数量不是人工正确率，也不能形成产品优越性
结论。Tavily 成功响应未返回服务端 credits 字段，运行记录保留 `null`，并依据 basic
search 计费口径单独估算为 8 credits，不能把估算冒充服务端用量。

## 4. 盲评与复核范围

评审页面只导入盲评包。每题三个答案随机映射为 A/B/C，页面仅显示
`hidden-until-adjudication`；实际 arm、模型和运行 ID 只存在于单独身份映射中。保存答案与
证据判断前不得打开身份映射。

每个候选答案建立 `benchmark_answer` 审核对象；其中每个系统原子结论建立独立的
`answer_claim` 对象。复核字段包括问题有效性、答案正确性、证据支持、引用对应、多要点
完整性、拒答合理性、严重度和错误分类。

为避免结构化输出格式泄露系统身份，三组答案在进入盲评包时统一切分成仅包含结论文本与
引用编号的中立格式；本系统内部的主体、谓词、支持类型和自动校验结果不会出现在盲评
对象中。未完成的盲评字段也不预选“正确”。

- 120 题全部需要第一复核；
- 20 道高风险题全部需要第二独立复核；
- 普通题按题集哈希稳定抽样 25 道进行第二复核；
- 共 45 题进入双人复核，即 360 次第一复核和 135 次第二复核；
- 核心字段不一致时必须由 `adjudicator` 裁决，否则汇总状态保持未完成。

评审者标识、自由文本备注和原始导出只保存在私有运行环境。公开 Bad Case 与回归候选不含
上述字段。

## 5. 汇总、Bad Case 与回归提升

完成复核后导出去身份化的候选评分，再生成汇总：

```powershell
python -m adc_evidence.evaluation.benchmark export-reviews --comparison-run-id COMPARISON_RUN_ID --output artifacts/evaluation/v0.6_benchmark/reviews.jsonl
python -m adc_evidence.evaluation.benchmark summarize --reviews artifacts/evaluation/v0.6_benchmark/reviews.jsonl
```

汇总只使用已满足复核范围、且分歧已裁决的人工结论。Bad Case 只收录人工确认的错误或部分
正确项；只有 `adc_evidence` 组的人工确认 Bad Case 才生成回归候选。候选仍需隐私检查和
人工批准，才能进入公开的 `data/annotations/v0.6_regression_questions.jsonl`。

公开回归集当前保留上一阶段已确认的 `gen_profile_005`，用于防止多字段回答再次遗漏。它
不代表本轮三组对照已经完成。

## 6. 发布门禁

满足以下条件后才能把阶段 5 标为通过：

- 三组均完成同窗 120 题运行，报告校验通过；
- 测试集没有在运行前用于调整实现；
- 495 次规定复核完成，所有分歧已裁决，并报告一致率；
- 发布人工指标、样本量、模型与数据版本和局限，不用自动分数替代人工结论；
- 原始评审者身份、备注、外部回答和身份映射未进入公开仓库；
- 人工确认的本系统 Bad Case 已生成并审核回归候选。

## 7. 已知局限

- 公开样例库不是完整生产数据，时间敏感问题可能暴露数据缺口；
- 联网组的可重复性受搜索结果和访问时间影响，必须保留来源与时间；
- 当前只有 8 题开发集真实链路运行，不包含任何虚构的专家评分；
- 若模型版本、数据版本、prompt、题目或同窗改变，结果不得与本轮直接合并。
