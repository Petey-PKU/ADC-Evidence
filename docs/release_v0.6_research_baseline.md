## 已准备的本地运行材料

生成材料放在被 Git 忽略的 `artifacts/evaluation/research_preparation/`：

- `question_manifest.json`：120 题规范化版本清单；
- `direct_request.json`、`web_request.json`：两组各 120 个请求，不含 required_terms、gold
  文档、预期路由或标准答案；
- `environment.json`：观察到的依赖版本，不含密钥或本机安装路径；
- `readiness.json`：只读数据检查的计数与哈希，及尚未满足的运行条件。

请求中的 `preparation-only-not-an-evaluation` 仅标记准备工作，不能作为正式同窗 ID。
它们不是模型输出；正式窗口确定后，应使用实际窗口重新生成请求与报告。

## 继续运行的交接

1. 指定正式评测数据库、来源快照与时间截止点。私有输入只在明确授权的运行环境使用，
   不复制进公开仓库；跨仓库操作前列出精确文件和隐私检查结果。
2. 在本地安全配置模型与 Tavily 凭据，或明确指定 `ADC_ENV_FILE`。禁止在对话、源码、
   报告或公开提交中粘贴真实密钥。先在开发题验证连接。
3. 记录数据/索引/代码/模型/prompt 版本和运行窗口，确认评审安排，然后运行三组。
4. 按阶段 5 工具产生盲评对象，再由真实人员复核。495 次是答案级复核数量，结论级审核
   和裁决另计。没有第二位人员时，保留待审状态。
5. 复核完成后按研究协议分别报告开发集与测试集；根据已冻结的分析计划实现统计和消融。

现有三组 CLI 详见 [阶段 5](v0.6_stage5_benchmark_review.md)。系统组默认使用
`ExtractiveGenerator`，两组外部模型保持同型号；论文必须如实描述这个区别。
