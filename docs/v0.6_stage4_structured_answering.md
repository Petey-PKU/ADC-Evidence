# v0.6 阶段 4：结构化优先问答与结论验证

状态：已实现，待阶段 5 冻结题集与对照评测
产品任务：JT-01、JT-02、JT-03、JT-04、JT-05
实现版本：`v0.6-structured-validator-v2`

阶段 5 的私有数据诊断发现，含 ADC 名称的机制/研究问题可能被误分到结构化事实路由，
罗马数字试验阶段和来源采集失败问题也需要更明确的意图词。v2 增加了这些路由信号，并
收紧患者用药行动与临床/投资预测类问题的拒答门禁；冻结题集哈希和 v1 基线标签保持不变。

## 1. 阶段目标

阶段 4 把原有“检索后生成一段带引用文本”升级为可检查的证据问答流水线：

```text
问题安全检查
  -> 任务、实体和字段路由
  -> 结构化查询或文献检索
  -> 原子结论
  -> 逐条字段/文本支持校验
  -> 回答 / 部分回答 / 拒答
```

核心约束是结构化字段不得退回自由生成。ADC 字段、ADC 比较、变化事件和临床试验字段由
数据库值直接形成答案；只有文献机制或研究结论进入检索与可选模型生成。

## 2. 问题路由

`generation/structured.py` 在检索或模型调用之前生成 `QuestionPlan`。计划包含路由、理由、
置信度、已识别 ADC、字段、NCT、靶点和变化时间范围。

| 路由 | 数据路径 | 模型调用 |
|---|---|---:|
| `structured_fact` | 当前 ADC facts 与 fact_evidence | 否 |
| `comparison` | 2～10 个 ADC 的对齐事实单元格 | 否 |
| `change_query` | change_events，固定 1/7/30 天语义 | 否 |
| `trial_lookup` | ClinicalTrials.gov 标准化 trials 字段 | 否 |
| `literature_evidence` | PubMed 检索切片 | 可选 |
| `refusal` | 护栏或无法形成受支持计划 | 否 |

比较问题必须识别至少两个已收录 ADC。路由不确定、实体未知或任务不受支持时失败关闭，
系统不会把结构化问题发送给通用模型尝试补齐。

## 3. 原子结论协议

每个展示结论保存以下机器可读信息：

- `claim_id`；
- `subject_type` 与稳定 `subject_id`；
- `predicate` 和规范值 `value`；
- 用户可读 `text`；
- `citation_ids`；
- `support_kind`：`structured` 或 `text`；
- `validation_status`。

回答同时记录数据版本、模式版本、证据策略版本、语料版本、路由依据、生成后端和耗时。
试验与文档校验所读取的标准化行现在也纳入数据版本哈希。

## 4. 结构化字段校验

结构化结论必须同时满足：

1. 输出值与当前字段规范值完全一致；
2. 至少有一条字段级证据；
3. 引用 ID 必须属于该字段绑定的证据；
4. 缺失字段不生成结论；
5. 未解决冲突不选择单一值；
6. 查询异常时不退回 RAG 或模型常识。

ADC 字段和比较复用阶段 3 的证据卡与单元格查询。临床试验直接读取 NCT、阶段、状态、
疾病、干预、主要终点、入组和日期等标准化注册字段。

## 5. 文本支持校验

文献路由仍先执行问题护栏、限定 PubMed 检索、引用编号和逐行引用完整性检查。通过引用
检查后，系统把回答拆成原子行，并逐条确认该行的可核查术语是否出现在它所引用的片段中。

- 引用缺失或未知：整份生成文本失败关闭；
- 引用有效但某条结论缺少直接文本支持：删除该条，不把原文暴露为答案；
- 至少一条受支持：返回 `partial`，并列出匿名化的未回答项；
- 没有任何受支持结论：返回 `refused`；
- 全部受支持：返回 `answered`。

该校验是保守的直接支持门禁，不声称完成医学语义蕴含判断。严格失败关闭可能牺牲召回率，
阶段 5 将通过冻结题集和人工复核量化这一取舍。

## 6. 部分回答与拒答

`AnswerResult.status` 支持 `answered`、`partial`、`refused` 和 `error`。`partial` 必须同时
包含：

- 已通过校验的原子结论；
- 每条结论的证据引用；
- `unanswered` 清单；
- 每个未回答项的原因代码和用户可读解释。

当前原因包括缺少直接证据、来源冲突、无匹配记录和校验失败。只请求一个冲突或缺失字段
且没有任何可支持结论时返回拒答。

## 7. 页面与命令行

Streamlit 的“证据问答”标签页默认只显示研究问题。生成后端、检索模式和 top-k 被移动到
“高级诊断设置”，并明确仅影响文献路由。结果页展示问题路由、已支持结论数、引用数、
数据/策略版本、未回答项和字段级或文本片段证据。

命令行入口继续兼容原命令，并新增 `--database`：

```powershell
python -m adc_evidence.generation.answer "T-DXd 的靶点、载荷和 DAR 是什么？" `
  --backend extractive --database data/processed/adc_evidence.db
```

这类结构化问题即使选择远程后端也不会产生模型调用。

## 8. 自动测试

`tests/test_structured_answering.py` 固定以下失败关闭路径：

- 六类路由选择；
- 结构化字段绕过检索和生成器；
- 缺失字段显式部分回答；
- 冲突字段拒答且不泄露候选单值；
- 比较单元格值和字段证据绑定；
- ClinicalTrials.gov 标准化字段回答；
- 变化事件表回答；
- 篡改结构化值被校验器拒绝；
- 文本结论逐条支持校验；
- 部分支持时隐藏不受支持结论；
- 全部不受支持时拒答。

阶段 4 新增测试共 12 项；与原 generation 和阶段 3 workbench 的可运行回归共 34 项通过。

## 9. 阶段边界与下一步

阶段 4 实现的是执行与验证协议，还没有宣称其相对通用模型的效果优势。阶段 5 必须冻结
120 题题集，运行通用模型直接回答、联网回答和本系统三组对照，建立事实、冲突、变化、
试验、文献及拒答的审核对象，并把人工确认的 Bad Case 加入回归集。
