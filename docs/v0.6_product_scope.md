# v0.6 产品范围与用户任务规范

状态：阶段 0 基线
目标版本：v0.6 ADC Evidence Intelligence
规范语言：本文中的“必须”“不得”为发布门禁；“建议”为非阻断项。

## 1. 产品定义

ADC-Evidence v0.6 是面向 ADC 研发信息核查的证据工作台。它不以回答任意问题为目标，
而是帮助用户核查当前事实、比较 ADC、发现公开来源变化，并把每个结论绑定到可追溯的
来源、时间和审核状态。

产品承诺是：

> 对收录范围内的 ADC 研发事实，给出当前可获得的公开证据、版本和不确定性；证据不足
> 或冲突未解决时明确拒答或标记待审核。

产品不承诺：

- 提供诊断、处方、剂量或患者级治疗建议；
- 预测尚未公布的试验结果、商业成功率或未来监管决定；
- 仅凭模型常识补齐数据库中不存在的事实；
- 代替药学、医学、法规或投资尽调；
- 在 v0.6 覆盖全部 ADC 和全部全文文献。

## 2. 目标用户与核心任务

### 2.1 目标用户

首版面向三类用户：

1. ADC 研发或药学研究人员：快速核查结构、机制、试验和文献证据。
2. 研发情报与 BD 支持人员：比较候选 ADC，追踪公开研发状态变化。
3. 数据维护与领域复核人员：处理实体关联、字段冲突、变化事件和 Bad Case。

患者、临床处方者和自动化交易系统不是 v0.6 的目标用户。

### 2.2 必须完成的用户任务

| ID | 用户任务 | 系统输出 | 成功标准 |
|---|---|---|---|
| JT-01 | 核查一个 ADC 的结构和研发事实 | ADC 证据卡 | 每个非空字段可展开来源、证据时间和审核状态 |
| JT-02 | 比较 2～10 个 ADC | 结构化比较表 | 每个单元格可追溯，缺失和冲突不被模型补齐 |
| JT-03 | 查看最近 1、7、30 天公开来源变化 | 变化事件列表和前后值 | 事件绑定来源快照，可按 ADC、靶点、来源和类型过滤 |
| JT-04 | 核查一项临床试验 | 试验证据卡 | NCT、阶段、状态、干预和终点来自结构化注册字段 |
| JT-05 | 查询文献机制或研究结论 | 原子结论及支持片段 | 每个结论有直接支持片段；不支持的结论不展示 |
| JT-06 | 导出一次核查结果 | Evidence Brief | 导出包含数据版本、生成时间、字段证据和免责声明 |
| JT-07 | 审核机器结果 | 复核队列 | 审核与内容哈希绑定，内容变化后旧审核自动过期 |

### 2.3 v0.6 数据范围

v0.6 继续以 HER2 和 TROP2 为深度验证范围。范围扩展采用“先深后广”原则：先覆盖这两个
靶点下能够稳定识别的公开 ADC、试验和文献，再决定是否扩展更多靶点。固定的 10 个种子
ADC 继续作为回归样本，但不得再被解释为产品覆盖上限。

## 3. 产品信息架构

v0.6 页面按用户任务组织，不向普通用户暴露检索实现参数。

| 页面 | 主要内容 | 公开演示 |
|---|---|---|
| 数据概览 | 数据版本、最后更新时间、来源健康度、最近变化 | 只读开放 |
| ADC 证据卡 | 当前字段、历史值、来源、冲突和审核状态 | 只读开放 |
| ADC 比较 | 多选比较、证据展开、CSV/Markdown 导出 | 只读开放 |
| 变化中心 | 新增记录和字段变化、前后值、过滤器 | 只读开放 |
| 证据问答 | 结构化查询或文献 RAG、原子结论和证据 | 限流开放 |
| 专家复核 | 事实、冲突、变化和回答审核 | 仅内部环境 |

sparse、dense、hybrid、top_k 和模型后端仅保留在高级诊断区或评测命令中。

## 4. 问题路由规范

系统必须先判断任务类型，再选择数据路径。

| 路由 | 典型问题 | 数据路径 | 生成模型职责 |
|---|---|---|---|
| structured_fact | “T-DXd 的 DAR 是多少？” | 事实表和字段证据 | 可选自然语言改写，不决定事实值 |
| comparison | “比较 Dato-DXd 和 Trodelvy 的 payload” | 多实体结构化查询 | 总结已验证差异 |
| change_query | “最近一周有哪些试验状态变化？” | 变化事件表 | 总结事件，不创造事件 |
| trial_lookup | “NCT06394492 当前状态是什么？” | ClinicalTrials.gov 标准化字段 | 可选改写 |
| literature_evidence | “有哪些 T-DXd 耐药机制研究？” | PubMed 检索和证据片段 | 生成原子结论 |
| refusal | 医疗建议、未来预测、缺失实体 | 护栏和证据检查 | 不调用或只返回受控拒答 |

路由不确定时可以执行受限检索，但不得把结构化字段退化为自由生成答案。

## 5. 端到端用户流程

### 5.1 核查与比较

    选择/搜索 ADC
      -> 加载当前事实视图
      -> 标记缺失、冲突、过期和待审核字段
      -> 展开字段级证据
      -> 可选加入比较
      -> 导出带数据版本的 Evidence Brief

### 5.2 变化追踪

    选择时间范围或 ADC
      -> 查询变化事件
      -> 查看旧值、新值和来源快照
      -> 标记重要/待审核事件
      -> 进入对应 ADC 或试验证据卡

### 5.3 证据问答

    问题安全检查
      -> 任务和实体路由
      -> 结构化查询或文献检索
      -> 生成原子结论
      -> 逐条验证证据支持
      -> 回答 / 部分回答 / 拒答

“部分回答”必须列出已回答字段和缺少直接证据的字段，不能静默遗漏。

## 6. 功能边界

### 6.1 v0.6 必须交付

- 不可变来源快照和采集运行版本；
- 时间化事实、字段级证据和来源冲突表示；
- 新增记录及关键字段变化检测；
- ADC/试验证据卡；
- 2～10 个 ADC 的结构化比较；
- 结构化优先的问题路由；
- 回答原子化和字段级支持验证；
- 数据、索引和导出版本绑定；
- 通用模型直接回答、联网回答和本系统的冻结测试对照。

### 6.2 延后到 v0.7 或以后

- 用户账号、团队空间和复杂权限；
- 邮件、企业微信等外部主动推送；
- 付费订阅和多租户；
- 全文 PDF 批量解析；
- 多实例写入和 PostgreSQL 迁移；
- ADC 成功概率、疗效或投资价值预测；
- 面向全部靶点的无边界自动扩库。

## 7. 非功能要求

- **可追溯**：所有展示事实必须能够定位来源记录或证据片段。
- **时间明确**：区分采集时间、来源更新时间和事实有效时间。
- **可复现**：回答与导出必须记录数据库版本、索引版本和策略版本。
- **失败关闭**：证据验证失败时不展示未经支持的生成文本。
- **可回滚**：新数据版本未通过质量门禁时不得替换线上版本。
- **隐私隔离**：公开仓库不得包含评审者身份、私有评测原文、凭据或服务器秘密。
- **成本受控**：结构化查询不得无条件调用 LLM；公开问答需要缓存和限流。

## 8. 产品决策记录

阶段 0 固定以下决策，后续若变更必须在发布说明中记录原因：

1. 产品竞争点是证据、时效、比较和复核，而不是开放域回答覆盖率。
2. v0.6 继续深耕 HER2/TROP2，不以盲目扩充靶点数量作为发布指标。
3. 结构化事实优先于 RAG；LLM 不作为结构化事实数据库。
4. 来源冲突必须保留，不能用“最后写入”静默覆盖。
5. 公开演示可以不开放远程 LLM，但必须展示证据卡、比较和变化价值。
6. SQLite 在单机 v0.6 继续使用，多实例并发写入前再评估 PostgreSQL。
