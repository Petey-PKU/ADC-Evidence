## 测试集使用状态

完整题集的诊断结果已被用于 v2 及后续实现调整。因此文件名与原始 `dev`/`test` 标签
继续保留用于历史复现，但当前用途为 **development_exposed（已用于开发）**。后续重复
运行只能报告探索性分析或开发回归，不得称作未见测试集验证。

manifest、后续请求及运行报告增加 `evaluation_use` 元数据，将
`eligible_for_unseen_test_claim` 标为 `false`。`implementation_frozen_after` 始终记录
原冻结实现 v1，当前代码版本另存于 `current_implementation`，避免历史冻结点随代码
更新而被改写。旧报告与已有 Git 标签均保留。

新的确认性评测需要独立构建并封存的保留集，不能通过改名、重新划分旧题或改写旧题面
获得。新题应由未参与当前路由调试的人员按照任务和证据来源抽样，记录截止时间、正确
答案、支持证据、可回答范围和歧义；在实现与分析方案锁定后再揭盲运行。当前尚未创建
这样的保留集，也未完成独立人工复核。

## 通用实现修复

- 注册试验中的比较对象可能是化疗；比较措辞不会再抢占试验注册字段路由。
- “不同/异同”能够形成 ADC 字段比较；综述、客观缓解率和最大耐受剂量问题进入文献
  核查，缺少证据时不会退回药物简介。
- 指定数据库同时传入结构化引擎和默认文献检索器；显式注入另一个真实检索数据库时
  报错。双数据库公开夹具验证返回的文献引用来自指定库。

原实现没有把 `--database` 传给默认检索器。因此旧的自定义数据库运行可能混用结构化
库与默认检索库；旧结果不能代表同一个证据快照，也不能与修复后的结果直接做纯算法
效果归因。后续复核应重新记录数据库、语料及实现版本，并核对全部引用来源。

## 可复现审计

使用安装了项目依赖的环境。在 Windows 终端读取中文时显式设置 UTF-8；终端显示异常时
先检查 Unicode 码点与文件字节，不直接重写输入文件。

```powershell
$env:PYTHONIOENCODING='utf-8'
$env:PYTHONPATH='src'
.venv/Scripts/python.exe -m adc_evidence.evaluation.question_audit --output artifacts/evaluation/question_audit.json
.venv/Scripts/python.exe -m unittest discover -s tests -v
```

已有系统报告可增加 `--system-report REPORT_PATH`。输入或结果涉及私有数据时，审计输出
也必须指定在私有评测目录；每次使用新文件名，工具拒绝覆盖已有产物。

审计检查原始字节、题目文本、唯一标识、题集哈希、每题恰好一个输出，并使用
`load_benchmark_questions()` 的完整规范化 ID 关联结果。特别是开发题 ID 含
`dev_retrieval_` 或 `dev_generation_` 前缀，不能只连接原始 JSONL 的旧 ID，否则会漏报
开发题失配。报告分别给出 dev/test 的分母、路由失配、缺失路由、状态和错误数。
缺少路由的行也计入分母；输出不包含原始答案、引用片段或评审身份。

这些检查属于工程质量审计，不能替代语义正确性、证据覆盖、来源时间与拒答合理性的
独立人工判断。`answered` 状态及自动支持标签不等于真正回答了问题。

本次在项目现有 Python 3.12 虚拟环境中通过全部 122 项单元测试与 `compileall`。
原先 4 项 SDK 导入失败来自使用了另一个系统 Python；项目环境已具备依赖，SDK 单元
测试只使用伪客户端，没有调用远程模型。后续测试夹具改用仓库内的工作区临时目录适配器，
因此当前公开分支的完整测试套件已在同一环境通过 156/156；这不改变本报告记录的历史题集状态。
