# v0.6 阶段 1：事实与历史数据层

状态：已实现
完成日期：2026-08-21
策略版本：0.6.0
数据库模式版本：0.6-facts-v1

## 1. 阶段目标

阶段 1 在不破坏 v0.5 查询和页面的前提下，为 v0.6 增加时间化证据数据层。旧表继续提供
当前 ADC、试验、文献和检索数据；新表并行保存不可变来源快照、事实版本、字段级证据和
变化事件。

本阶段不包含定时调度、完整采集集删除判断、增量索引和新页面。这些能力属于阶段 2、3。

## 2. 新增数据库对象

| 表 | 用途 |
|---|---|
| schema_versions | 记录已经应用的模式版本 |
| source_snapshots | 按来源、记录和内容哈希保存不可变快照元数据 |
| facts | 保存原子事实的当前、历史或冲突版本 |
| fact_evidence | 把事实版本绑定到来源快照、字段位置和证据文本 |
| change_events | 保存字段变化、冲突产生和冲突解决事件 |

create_database 会对既有数据库执行仅新增对象的向前兼容迁移，并登记
0.6-facts-v1。原有表、列和数据不会被删除或重写。

## 3. 来源快照语义

快照 ID 由 source、source_record_id 和 SHA-256 内容哈希确定。同一记录、同一内容重复
采集只保留一份快照；source_records 仍更新为最新抓取指针。

source_snapshots 记录：

- 首次取得该内容的时间；
- 来源声明更新时间；
- 来源 URL 和原始文件路径；
- 内容哈希、数据集版本和解析器版本；
- 可选的采集运行 ID。

verify_source_snapshots 会重新读取原始文件，并返回 valid、missing 或 hash_mismatch。
验证函数只报告异常，不自动改写或删除快照。

## 4. 事实写入语义

FactObservationSet 表示某一来源对一个主体、一个谓词的完整观察集合。使用“完整集合”而
不是逐值更新，可以正确表达多值字段删除，例如试验阶段从 PHASE1、PHASE2 变为仅
PHASE2。

写入过程：

1. 校验谓词、来源、审核状态和快照身份；
2. 对规范值生成稳定哈希；
3. 相同观察幂等跳过；
4. 关闭该来源旧的当前证据；
5. 复用相同仍有效事实或创建新事实版本；
6. 根据字段策略计算 current、superseded 或 conflicted；
7. 记录字段变化、冲突产生或冲突解决事件。

同一来源更新会关闭旧事实的有效区间。不同来源对 require_review 字段给出不同值时，两个
值都保留为 conflicted，不采用最后写入覆盖。来源后来变为一致时，旧冲突值转为
superseded，并产生 fact.conflict_resolved 事件。

## 5. 当前采集集成

采集管线已经接入以下转换：

| 来源 | 事实主体 | 解析器标识 |
|---|---|---|
| 公开种子 CSV | ADC | curated_seed_v1 |
| ADCdb | ADC | adcdb_structured_v1 |
| ClinicalTrials.gov | 临床试验 | clinicaltrials_structured_v1 |
| PubMed | 文献 | pubmed_structured_v1 |

ADCdb 事实仅使用 ADCdb 原始记录实际存在的字段。标准化 ADCRecord 中由种子数据回填的
字段不会被错误归因给 ADCdb。

临床试验字段使用 ClinicalTrials.gov 结构化注册数据；PubMed 当前保存题名、摘要和发表
日期。publication_type 暂时以空观察集合保存，等待来源解析器后续补充。

## 6. 查询接口

- list_current_facts：按主体、ID和谓词查询 current/conflicted 事实及其当前来源；
- list_change_events：按主体或事件类型查询变化历史；
- verify_source_snapshots：验证原始文件与快照哈希；
- data_quality_metrics：新增快照、当前事实、冲突事实和变化事件数量。

当前页面尚未使用这些接口，避免在数据层稳定前同时引入 UI 变化。

## 7. 已验证路径

自动测试覆盖：

- 既有数据库迁移且不丢失 10 条 ADC；
- 同内容重复采集只产生一个快照；
- 当前来源指针可以更新而旧快照保持不可变；
- 原始文件篡改能够被哈希验证发现；
- 相同事实重复写入幂等；
- 同一来源字段变化生成历史版本和变化事件；
- 多值字段变为空时旧事实被正确关闭；
- 跨来源冲突被保留，来源重新一致后可以解决；
- 完全离线、跳过三个外部来源的采集管线仍能同步种子事实。

## 8. 阶段边界与下一步

阶段 2 需要在此数据层上实现：

1. 分来源计划任务、锁和失败重试；
2. 采集运行完整性与数量异常门禁；
3. 只有完整成功运行才能判断 source.record_missing；
4. 基于受影响记录的增量检索文档和索引更新；
5. 数据库版本与索引 manifest 绑定；
6. 预发布、备份、原子发布和失败回滚。

原始批次文件可能同时承载多条来源记录，因此多个 source_snapshot 可以引用同一文件。
阶段 2 可增加记录级规范内容哈希以减少批次中无关变化造成的快照增长。
