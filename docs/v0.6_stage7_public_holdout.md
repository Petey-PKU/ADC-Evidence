# v0.6 Stage 7: public smoke holdout

The repository now contains a separate public smoke holdout at
`data/annotations/v0.6_public_holdout_questions.jsonl`. It has 20 questions
covering structured facts, comparisons, unsupported fields, and refusal
boundaries. None of its rows are copied from the exposed 120-question
development benchmark.

## Reproduce

```powershell
$env:PYTHONPATH = "src"
.venv\Scripts\python.exe scripts\run_public_holdout.py `
  --database data\processed\adc_evidence.db `
  --questions data\annotations\v0.6_public_holdout_questions.jsonl `
  --window-id public-holdout-20260913-v1 `
  --output artifacts\evaluation\public_holdout_20260913.json
```

The run records version `v0.6-public-holdout-20q-2026-09-13` and question-set
hash `sha256:987eef64df96fd1813f8f8abb65648bba78dc815658a9bde5b0e5f846ae08ffb`.
Both local arms run with `network_enabled: false`.

## Interpretation

On the public sample database, the structured arm achieved automatic route and
expected-status match rates of 1.0 with zero runtime errors. The extractive
baseline had an automatic route match rate of 0.15 and expected-status match
rate of 0.95. These are deterministic engineering diagnostics, not semantic
correctness scores. Because the questions are public and may inform development,
they are not eligible for an unseen-test publication claim. Before making a publication claim, the project needs
source-level checking and a larger domain-curated set.

The workflow also exposes `validate_holdout_disjoint()`, which rejects both question-ID overlap and normalized exact wording overlap with an exposed set. A changed wording that preserves the same underlying question remains a methodological concern and requires manual dataset review.
